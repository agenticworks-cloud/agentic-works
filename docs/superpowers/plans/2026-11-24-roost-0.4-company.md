# Roost 0.4: a company file, Connect Claude, and Connect your tools — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Roost 0.4 reads a company's `~/.config/roost/company.json` and walks a person through connecting Claude
(company gateway, generic gateway, subscription, Anthropic API key, Bedrock, or Codex only) and their company's MCP
servers, with the installer installing `git` and Homebrew's `shellenv` properly.

**Architecture:** One loader (`company.js`, a copy in Roost's `src/` and in `parts/agents/src/`, since a part never
requires Roost's `src/`) validates the company file into a normalized object. The Agents part grows a key check
(`gatewayCheck.js`), a terminal-`claude` writer (`terminalClaude.js`), and a **Connect Claude** panel that composes
them with the existing gateway form and Claude login. Roost's own `src/` grows a stdio MCP client, a Claude Code
user-scope registrar and a **Connect your tools** panel; the walkthrough wires them in.

**Tech Stack:** Plain Node.js (CommonJS) VS Code extension, no build step; `node:assert` tests with the existing
`vscode` stubs; jsdom (from a part's `node_modules`) for page tests; bash 3.2 + Python `unittest` for the installer.

**Spec:**
- `/git/roost/docs/notes/101-roost.md`, *Follow-ups*: "Agents: a company's gateway, ready but for the key (design,
  for 0.4)" (superseded in part) and "A company file, Connect Claude, and Connect your tools (design, for 0.4;
  supersedes the preset above)", and *Settled while planning 0.4* (this plan's decisions, copied there).
- `/git/roost/docs/notes/102-roost-installer.md`, step 4a (git installed explicitly).
- Context (why each piece exists, one company's concrete use; nothing of it goes into this repo): a note in that
  company's installer repo, kept outside this one.

## Global Constraints

- Nothing company-specific in Roost's repo: no company's URLs, app or tenant IDs, model names or product names, in code,
  docs or tests. Tests use `example.com`-style hosts and `Example Gateway`-style names.
- A part never requires Roost's `src/`: `parts/agents/src/company.js` is a byte-identical copy of `src/company.js`,
  checked by a Roost test (as `settingsCarryOver.js` is).
- No new runtime npm dependency. Page tests load jsdom from `parts/agents/node_modules`.
- Unchanged ids: existing commands, views, webview types and context keys keep their names (101 anti-goal).
- Secrets (keys, tokens) are written mode 0600 in a 0700 directory, never sent to a webview, never put in a process's
  argv, and never written to Roost's or a part's output channel.
- `~/.claude/settings.json` and `~/.claude.json`: a value the user already has is replaced only when they agree; a
  file that does not parse as a JSON object is never rewritten (the panel says why).
- Company file: `~/.config/roost/company.json`; `ROOST_COMPANY_FILE` overrides the path (tests and company installers).
- Context keys: `roost.company` (a valid company file), `roost.companyTools` (valid, with at least one MCP server),
  `roost.toolsConnected`, `perch.claudeConnected`; `perch.gatewayReady` and `perch.messageSent` as today.
- The walkthrough's text is static: anything that depends on the company file is in a panel, not a step's text.
- Installer: bash 3.2 compatible, every new step one checklist line, safe to run again, `--yes` never answers a sign-in.
- The root `package.json` is generated: run `make manifest` after any `contributes` change; `make test` green at the
  end of every task.

## Review Focus

1. **`~/.claude.json` rewritten by a running Claude Code** while Roost registers a server: Roost re-reads it
   immediately before writing, keeps every other key as it found it, and writes atomically (temp + rename); a file that
   doesn't parse is left alone. Test: Task 6, `claudeMcp.test.js` "keeps keys written after the first read".
2. **A laptop off the VPN** starting a Claude tab on the company gateway: no address answers; the tab starts on the
   gateway file's address after at most 3 s per address, never hangs. Test: Task 3, `gatewayCheck.test.js`
   "probe gives up per address".
3. **An MCP server that misbehaves on stdio** (exits at once, prints non-JSON on stdout, never answers): the row says
   why, the process is killed, nothing is left running. Test: Task 6, `mcpClient.test.js` modes `exit`, `garbage`,
   `silent`.
4. **A settings file the user hand-edited** (`~/.claude/settings.json` with `//` comments, or an array): Connect
   Claude saves the connection for tabs, leaves the file alone and says so. Test: Task 4, `terminalClaude.test.js`
   "an unparsable settings file is never rewritten".
5. **A key pasted with spaces or a trailing newline**: it is trimmed before the check and before it is saved, in the
   gateway form, the API key field and the tools token field. Tests: Task 3 (`checkKey` gets `' sk-1\n'`), Task 5,
   Task 6 (`saveToken`).

- Produces: `STEP_NAMES="vscode path standalone roost companions git github homebrew settings icons open"`;

  seams `ROOST_INSTALL_GIT` (the git path taken as found) and `ROOST_INSTALL_CLT_WAIT` (seconds to wait for Apple's
  Command Line Tools, default 600, polled every 5 s, or every 1 s when the wait is under 10 s).

Rules this task implements:
- **git works** when `git --version` exits 0. On macOS, when git is `/usr/bin/git` and `xcode-select -p` fails, git
  is not run at all (the shim would open Apple's dialog) and counts as missing.
- **Installing:** macOS with Homebrew: `brew install git`. macOS without: `xcode-select --install`, then wait
  (`ROOST_INSTALL_CLT_WAIT`) for `xcode-select -p`; on timeout `✗ git: finish the Command Line Tools install Apple
  opened, then run git --version`. Ubuntu/Debian: `apt-get install -y git`; RHEL/Fedora: `dnf install -y git`, both
  with `$SUDO`. `system_changes` lists `git` on Linux when it will be installed.
- Lines: `✓ git (already)`, `✓ git (installed)`, `✗ git: couldn't be installed; see <log>`. Skipped with the rest of
  steps 4–7 when the standalone-four question was answered Stop.
- **Homebrew on the PATH** (macOS only): `HOMEBREW_USED=1`, or Homebrew is present and `code`, `gh` or `git`
  resolves inside its bin directory. Then, unless the login profile already has a `brew shellenv` line or
  `ORIG_PATH` already holds that bin directory, append
  `# added by roost-install: Homebrew` / `[ -x <brew> ] && eval "$(<brew> shellenv)"` / `# end roost-install`.
  No line at all when Homebrew wasn't used; `✓ Homebrew on the PATH (already)` when the profile has it.

    `connect = { kind: 'tokenPage'|'command'|'mcpTool'|'none', page?, command?: string[] (first word absolute), tool?, args: object, complete: object|null, doneWhen: { file (absolute) }|null, check: Check|null }`;

Validation rules: the file is a JSON object with a non-empty `name`. `gateway`, when present: `name`, `baseUrls`
(non-empty, each http/https), `keyPage` (http/https); `requiredModel` string, `env` string→string, `keyFiles`
string array, `terminal` boolean, each optional. `mcpServers`, when present: an array; `id` matches
`/^[A-Za-z0-9_-]+$/` and is unique; `name`, `about` strings; `register.type` `http` (with `url`) or `stdio` (with
`command`); `connect.kind` one of the four; `tokenPage` needs `page`; `command` needs `command` (array) and
`doneWhen.file`; `mcpTool` needs `tool` and a `stdio` register; `${token}` may appear only in a `tokenPage` server's
`register`. `check` is `{ method, url, body }`, `{ mcpTool, args? }` or `{ command: [...] }`. `~` and `~/` expand
to `home` in `keyFiles`, `register.command`, `connect.command[0]`, `doneWhen.file`. Unknown keys are ignored. Any
error makes the whole file invalid, and the error names the path (`mcpServers[1].connect.kind: …`).

**Interfaces:**
- Consumes: `readCompany`, `companyFile` (Task 2, agents copy).
- Produces:
  - `probeBaseUrls(baseUrls: string[], { key: string, fetch?, timeoutMs = 3000 }): Promise<string|null>` — the first
    URL whose `GET <url>/v1/models` gives any HTTP answer; null when none does.
  - `checkKey({ baseUrls, key, requiredModel = '', name = 'the gateway', style = 'gateway'|'anthropic', fetch?, timeoutMs = 10000 }): Promise<{ verdict: 'works'|'missingModel'|'rejected'|'unreachable'|'unexpected', baseUrl: string, models: string[], status: number, text: string }>`
    — the key trimmed; `gateway` style sends `Authorization: Bearer` and `x-api-key`; `anthropic` style sends
    `x-api-key` and `anthropic-version: 2023-06-01`. URLs in order; the first that answers decides (a 401 from the
    first is final). 2xx with a `data` array of ids: `works`, or `missingModel` when `requiredModel` isn't among them
    (compared with a leading `anthropic/` removed from both). 401/403: `rejected`. Any other answer or body:
    `unexpected`. None answered: `unreachable`.
  - Verdict texts (exact): works `Works.`; missingModel `The key works, but its scope lacks ${requiredModel}.`;
    rejected `${Name} rejected the key.`; unreachable `Can't reach ${name}: on the VPN?` when `baseUrls.length > 1`,
    else `Can't reach ${name}.`; unexpected `${Name} gave an unexpected answer (HTTP ${status}).` (`${Name}`: `name`
    with its first letter capitalised).
  - `writeSecretFile(file: string, value: string): void` — dir 0700 (made), file 0600, `value + '\n'`, chmod after.
  - `saveKeyFiles(files: string[], key: string): string[]` — the paths written.
  - `saveGateway(file, { baseUrl, token, models?, env? })` — `env` entries written as `export K=V` lines, like models.
  - Gateway form state gains `preset: { name, keyPage, baseUrl: string } | null` (`baseUrl`: the address saved, or '').
    Page → host: `getKey`; `save { baseUrl, token, models, force }`. Host → page: `verdict { text, canForce }`.
  - `PerchView#company(): ReturnType<readCompany>` (read on each call); `PerchView#companyGateway(): CompanyGateway|null`;
    `PerchView#onGatewaySaved: Set<(gw) => void>` called after each successful save.
  - `resolveGatewayTarget(gateway: { target, candidates?: string[], key? }, { fetch? } = {}): Promise<string>` exported
    from `claudeAgent.js`: `probeBaseUrls(candidates, { key })`, else `target`. `_run` awaits it before the relay.
  - `ensureAgent` passes `gateway: { target: gw.vars.ANTHROPIC_BASE_URL, candidates: companyGateway ? companyGateway.baseUrls : [], key: <the file's token> }`.

Form rules. With a company gateway (`companyGateway()` non-null): heading `Connect to ${preset.name}`, no Base URL
field and no model names (the company's `env` is written instead), a **Get a key** button (opens `keyPage` with
`vscode.env.openExternal`), a Key field (password) and **Check and save**; on `works` the gateway file gets
`ANTHROPIC_BASE_URL` (the address that answered), `ANTHROPIC_AUTH_TOKEN` and `env`, each `keyFiles` entry gets the
key, and the Saved box shows "Answered at <baseUrl>." and **New Claude Tab on the Gateway**. Any other verdict: its
text, nothing written, `canForce: false`. Without one: today's fields; Save becomes **Check and save** against the
typed base URL; on `unexpected` only, `canForce: true` shows **Save anyway**, which saves unchecked. A key already
saved shows as set with **Replace**; Check and save with the key kept checks the saved one.
