# Roost 0.5: a Get started page of its own — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A **Get started** editor tab of Roost's own, opened by first start and by **Roost: Get Started**, where every step works in place, with its title and two step names taken from the company file.

**Architecture:** The page (`src/getStartedPage.js`, no VS Code) and its host (`src/getStarted.js`) live in Roost's `src/`. The host reaches part logic only through commands the parts register, which take a message and return the replies their own panel would have been posted (`perch.connectClaude.request`, `jay.signInWith`); it learns the completion signals by watching the parts' `setContext` calls (`src/contextWatch.js`), as it already watches their serializers. The Connect Your Tools rows are one script shared by both of Roost's pages (`src/toolsRows.js`).

**Tech Stack:** Plain JavaScript (CommonJS, no build step), VS Code API `^1.90`, webviews with nonce CSP, Node's `assert` tests, jsdom (from `parts/agents/node_modules`) for page tests.

**Spec:** `docs/notes/101-roost.md`, Follow-ups, last bullet: *A Get started page of Roost's own, everything in place* (design, for 0.5), with its **Settled while planning 0.5** sub-bullet; the *First start* section and the 0.4.0, 0.4.2 and 0.4.3 bullets for what exists.

## Global Constraints

- No company names in the repo: `test/noCompanyNames.test.js` must pass. The company file supplies `title` and `steps.*`; tests use `Example Co` / `Example Gateway`.
- Secrets (gateway key, Anthropic API key, tools tokens, Jira API token) are written 0600, never sent to a webview, never put in argv, and never logged.
- No new runtime npm dependency. Page tests load jsdom with `require.resolve('jsdom', { paths: [path.join(root, 'parts', 'agents')] })`.
- The root `package.json` is generated: after any `roost.json`, `roost.contributes.json` or part `package.json` change, run `make manifest`.
- Version `0.5.0` (`roost.json`).
- A part never requires Roost's `src/`; `src/company.js` and `parts/agents/src/company.js` stay byte-identical.
- Command, view, webview-type and context-key ids already shipped keep their names.
- **Agents: Connect Claude…**, **Agents: Set Up a Gateway…** and **Roost: Connect Your Tools** keep working from their commands; the Get started page never opens them.
- VS Code's walkthrough stays as it is (Welcome page); first start opens the page instead.
- `make test` green at the end of every task.

## Review Focus

- A part off, failed or still starting when the page sends it a request (`perch.connectClaude.request` / `jay.signInWith` not registered): the step says `<part title> isn't running.`, its buttons work again, nothing is thrown. Test in Task 7.
- The page closed (or Roost stopping) while a long request is pending (Claude's subscription login, a tools sign-in, a Jira check): the late reply is dropped without an error; reopening shows the current state. Test in Task 7.
- A part switched off or on while the page is open: its steps go or come at once, and the open step moves to the first one not done. Test in Task 7.
- The page in a background tab while a key is half typed or a reply arrives: nothing lost (`retainContextWhenHidden: true`). Test in Task 7.
- A secret typed into the page turning up in a later message to the page, in the Roost output channel, or left in its field after submit. Tests in Tasks 6 and 7.

### Task 6: The Get started page

**Files:**
- Create: `src/getStartedPage.js`
- Test: `test/getStartedPage.test.js` (jsdom, as `test/toolsPage.test.js`)

**Interfaces:**
- Consumes: `TOOLS_ROWS_CSS`, `toolsRowsScript()` (Task 5).
- Produces: `getStartedHtml({ nonce, cspSource }) → string`, no VS Code. `<title>Get started</title>`.
- Host to page: `state {state}` where `state = { title, steps: [{ id, name, done, waiting }], claude: { companyGateway }, github: { logins }, teams: { rowId }, jira: { rowId, site, form }, parts: [{ id, title, on }] }`. `steps` holds only the steps shown, in order; ids `github`, `claude`, `agents`, `tools`, `teams`, `jira`, `codebase`, `parts`; `waiting` is a line shown while a sign-in is out in a browser or terminal (`''` otherwise); `claude.companyGateway` is the company gateway's name or `''`; `jira.form` is false when Jira signs in by its own token file. - Page to host: `ready`; `agents {request}` (Task 2's messages); `github`; `newTab {kind: 'claude'|'codex'}`; `notNow {step: 'claude'|'tools'|'codebase'}`; `codebaseOn`; `teamsSignIn`; `jiraSignIn`; `jiraForm {site, email, token}`; `part {id, on}`; `partsDone`; `openSettings`; `tool {message}` (a `ToolsList` row message, `{type, id, ...}`).
- Rules the page owns: the `h1` is `state.title`; each step is a section with its name and a tick when `done`; the first shown step not done is open, the others closed, and a click on a step's name opens or closes it; a typed secret field (`password`) is emptied as its message is posted.
- Each step's controls: **github** Sign In to GitHub (with logins: "Signed in as a, b." and Add Another Account), both posting `github`. **claude** with `companyGateway`: its name, Get a key (`agents {request:{type:'getKey'}}`), Key and Check and save (`gatewaySave` with `baseUrl: ''`, `models: {}`), the terminal box; without: the four ways inline — a gateway (Base URL, Token, Check and save, Save anyway on `canForce`), subscription (Log In), API key (Key, Check and save), Bedrock (Use Bedrock…, then Profile, Region, Check and save, Save anyway), the terminal box, Replace / Keep Mine on `conflicts`, and Not Now (`notNow {step:'claude'}`); both forms post `{type:'agents', request:{type:'gatewayReady'}}` and `{type:'agents', request:{type:'ready'}}` when the step first opens. **agents** New Claude Tab, New Codex Tab. **tools** a `ToolsList` of every row, and Not Now. **teams** the `rowId` row in a `ToolsList` of its own when set, else Sign In to Teams (`teamsSignIn`). **jira** the row likewise; else with `form`: Site URL (prefilled from `site`), Email, API token, a Create one link to `https://id.atlassian.com/manage-profile/security/api-tokens`, Sign in (`jiraForm`), the error under it; without `form`: Sign In (`jiraSignIn`). **codebase** Turn On (`codebaseOn`) and Not Now. **parts** one checkbox per part (`part`), Done (`partsDone`), All settings (`openSettings`).
